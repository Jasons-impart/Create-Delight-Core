# 模组兼容补丁

| 问题 | 外部触发条件 | 实现 | 验证与复核 |
| --- | --- | --- | --- |
| 品质酒丢失零时长即时效果 | QF 2.4.3 的 `FoodUtils.modifyEffect` 对有效品质统一过滤 `duration <= 0`，使森罗四款酒及招牌鸡尾酒中的即时效果在铁／金／钻品质下消失。 | `mixin/quality_food/FoodEffectQualityMixin` 仅将即时效果的时长判定阈值由 0 改为 -1，保留 QF 的等级、概率、黑名单及其他过滤；只需 QF 存在即可加载。机制与受影响酒见[品质机制](quality-food.md#即时效果与品质)。 | 回归覆盖四款真实酒效的四品质、实际瞬间治疗、签名杯 NBT，以及持续效果过滤和有害效果品质缩放。升级 QF 后复核三参数 `modifyEffect` 的描述符及唯一时长比较；上游正确支持即时效果后移除此补丁。 |
| 妖怪归家原生发酵与装排酒丢品质 | Youkai's Homecoming 2.7.0 的简单发酵重建物品／流体输出，原生酒瓶能力及发酵罐装瓶不经过 QFF 的 Create 注入。 | `mixin/youkaishomecoming/` 与 `compat/alcohol/YoukaiBottleQuality` 在扣料前快照物品和酒液，发酵共用一次 QFF 品质掷级；瓶／液互转原样继承。仅在 YH 与 QFF 同时存在时加载；装瓶使用真实方块交互作用域，在库存合并前写品质。 | 回归覆盖物品／流体共同参与、两类产物、无星清残留、原生小瓶往返及大瓶部分排液。升级 YH 或 QFF 后复核 `SimpleFermentationRecipe.results`、`finishRecipe`、wrapper `getFluid/setFluid` 与 `FluidItemTile.addFluidOrItem`；上游接入品质后评估移除。 |
| 森罗酒馆酒桶与 QF 品质不互通 | Tavern 1.2.0 的六档陈酿及饮品酒效不经过 QF；压榨新建无品质流体且忽略 fill 返回值；摇酒时长与无配方鸡尾酒绕过 recipe assemble，倒杯直接 setBlock，Mojito 倒杯／手动摆放漏存实体成品，Mojito／签名杯在全局掉落修饰后追加重建物品。六种果汁未进 QFF 流体白名单；CGT 1.2.0 仅把物品品质嵌入 `DrinkItemTag`，QFF 储罐和管道不识别该嵌套。 | `compat/kaleidoscopetavern/` 与对应 Mixin 按饮品类型接入 QF 品质与 `FoodUtils`，酒桶先等待 `unit_time` 完成基础酿造再开始基酒单次陈酿，醋仅酿造；待产出记录和两个阶段均持久化，基础酿造完成前实际输出槽保持空且流体能力无成品。鸡尾酒配方与兜底分别掷级，倒杯及两条最终掉落入口接 QF 位置品质，不另写饮品品质标记。压榨在原生比较前赋品质并模拟接收，KJS 补齐六果汁／桶及 CGT 基酒、醋与鸡尾酒流体标签；`DrinkFluidConversionsMixin` 桥接瓶液根品质。Jade 及 CGT 流体名不显示原生陈酿等级，创造栏通过 Forge 内容事件保序替换为钻品质；CGT 补丁按模组存在情况加载。 | 回归覆盖酿造等待、禁止提前出酒、醋品质与不陈酿、14 种鸡尾酒四档品质的配方／兜底、倒杯／摆放／取回及两类掉落路径；六种果汁桶原生桶槽往返已通过当前本地 QFF 构建回归、连续压榨与拒收不扣料、实际原料掷级、初酿上限、计时持久化、装瓶摆放与掉落、QF 酒效和调酒门槛、无额外标记及创造栏；本地 CGT 存在时额外执行全部受支持饮品四档瓶液转换。客户端显示由用户实测。升级 Tavern／QF／QFF／CGT 后复核原生压榨比较与扣料顺序、桶能力、瓶液转换签名、酒效数据和 Jade Provider。 |
| 魔法炼药锅品质流体无法匹配或丢星 | Iron's Spells 'n Spellbooks 1.20.1-3.16.3 的炼药锅在原生装瓶／倒液／酿造路径比较完整流体 NBT，并直接使用无品质配方模板；QFF 未覆盖该机器。 | `mixin/ironsspellbooks/{AlchemistCauldronQualityMixin,AlchemistRecipeQualityMixin}` 在配方匹配时仅去除品质字段，按实际批次消耗；酿造调用 QFF 的物品与流体共同掷级，装排液原样传递。 | 回归覆盖原生装排液、带品质输入酿造及无星清残留。升级 Iron's Spells 或 QFF 后复核 recipe `matches`、`tryMeltInput` 实际输出的第二次 `results()` 调用及 `tryExecuteRecipeInteractions`。 |
| 蟾蜍捕食极值伤害溢出 | Alex's Mobs 1.22.9 对绯红蚊捕食传入 `Float.MAX_VALUE`；AttributesLib 1.3.7 通用暴击放大后变成 Infinity，TetraWear 1.0.0 护甲研磨随后调用 BigDecimal 抛错。 | `mixin/alexsmobs/WarpedToadPredationDamageMixin` 将 tick 中绯红蚊分支唯一极值改为 10,000；保留普通攻击、伤害源及事件/死亡流程，模组缺失时跳过。 | 同一捕食补丁已在带诊断的测试包验证 10,000 普通捕食与目标生命归零；暴击和最高阶段组合没有完整实测。正式分支只含本补丁，不含临时探针或抗性重排。升级 Alex's Mobs 后复核 named/SRG tick 与唯一常量；上游改为安全有限伤害后评估移除。调查见 [CDC #126](https://github.com/Jasons-impart/Create-Delight-Core/pull/126) / [CDR #2298](https://github.com/Jasons-impart/Create-Delight-Remake/pull/2298)。 |
| 铜工作盆产出流体丢失品质 | FluidLogistics 的 `CopperBasinBlockEntity` 覆写了 `acceptOutputs`，有流体时把流体从父类调用里剥掉自行灌罐，导致 Quality Food Fluids 挂在父类方法上的品质注入拿到空列表并被跳过。 | `mixin/fluidlogistics/CopperBasinQualityMixin` 在该方法 HEAD 主动调用 `BasinRecipeQualityContext.applyToOutputs`，把品质写回 `outputFluids`；`CombatMixinPlugin` 要求 `fluidlogistics` 与 `quality_food_fluids` 同时加载才应用。 | 0.5.0.15 测试服以 hotai 字节码补丁等价实现验证通过（cosmopolitan 冰淇淋配方产出的流体带品质）。CDC 侧需在具备 fluidlogistics 1.3.0 与完整 JEI 依赖的环境补跑 build 与 runClient。详见 [铜工作盆产出流体品质修复](../../doc/copper-basin-fluid-quality-fix.md)。 |
